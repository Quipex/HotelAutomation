## Этап 9. Аудит и ABAC

**Цель:** обеспечить централизованное логирование всех действий пользователей и гибкий контроль доступа через политики на основе атрибутов.

---

### 1. Аудит (Audit)

- **Таблицы и сущности**  
  - `audit_actor` с полями: id, платформа, user_id, user_name, user_nick, user_agent, ip_address, created_at  
  - `audit_log` с полями: id, timestamp, actor_id → `audit_actor`, action, object_type, object_id, details (JSONB)  

- **Контекст пользователя**  
  - Использовать `AuditContextHolder` на основе `ThreadLocal` для хранения текущего актёра в рамках HTTP-запроса или обработки Telegram-сообщения  
  - При входе каждого запроса или обновления бота заполнять контекст активным пользователем (chat_id, username, платформа, ip, user_agent)  

- **Аннотация для методов**  
  - Создать `@AuditableAction`, принимающую параметры `action` и `objectType`  
  - Помечать ею все сервисные методы, где нужно фиксировать операцию  

- **Аспект аудита**  
  - В `AuditAspect` перехватывать вызовы методов с `@AuditableAction`  
  - До или после выполнения сохранять в `audit_log` запись с привязанным `actor_id`, именем действия, типом объекта, идентификатором объекта (из аргументов или результата) и дополнительными данными в JSON  

- **Проверка**  
  - Unit-тесты для `AuditAspect`, мокая `AuditLogRepository`, убеждаться, что запись создаётся с правильными данными  
  - Интеграционные тесты HTTP и Telegram, проверяющие появление записей в `audit_log` после выполнения команд  

---

### 2. ABAC (Attribute-Based Access Control)

- **Файл политик**  
  - `abac-policies.yml` с набором именованных политик, каждая содержит SpEL-условие на атрибуты пользователя и параметров (например, `role == 'admin' or role == 'manager'`)  

- **Загрузка и валидация**  
  - При старте приложения парсить `abac-policies.yml`, проверять синтаксис SpEL  
  - При ошибках отправлять экстренное уведомление администратору через `NotificationService`  
  - Предусмотреть REST-эндпоинт `/api/policies/reload` для динамической перезагрузки  

- **Аннотация для защиты**  
  - `@CheckPermission("policyName")` для методов, требующих проверки  
  - Если для данного имени нет политики или условие не выполнено – по умолчанию отказать (AccessDenied)  

- **ABAC-аспект**  
  - В `AbacAspect` перехватывать методы с `@CheckPermission`  
  - Искать политику по имени, если не найдена – выбрасывать отказ  
  - Вычислять результат SpEL на базе атрибутов пользователя из контекста и аргументов метода  
  - При false – выбрасывать AccessDenied до выполнения метода  

- **Команда для бота**  
  - Добавить `/reload_abac` в Telegram-бот, вызывающую эндпоинт перезагрузки политик и сообщающую результат  

- **Тестирование ABAC**  
  - Unit-тесты для загрузчика политик (валидный/невалидный YAML)  
  - Unit-тесты для `AbacAspect`, проверяющие отказ при отсутствии или несоответствии условия  
  - Интеграционные тесты REST, убеждающиеся, что без соответствующей роли запросы получают 403
